# Takamol Plus Interface

# برومبت Lovable — واجهة تكامل بلس (صورةً صورة)




> ثلاثةُ نصوص: **الأولى** مع أوّل صورة، و**المتكرّرة** مع كلّ صورةٍ بعدها،

> و**نصُّ التصحيح** حين ينحرف. أكثرُ ما ستستعمله هو الثاني — وهو قصيرٌ عمداً.




---




## الخطرُ في إرسال الصور واحدةً واحدة




Lovable لا يتذكّر «أسلوباً» — يتذكّر **ما في الدردشة**. فإن بعثتَ الصورةَ

الثانية بلا تقييد، بنى لها ألواناً وحوافَّ وحجومَ خطٍّ جديدةً قريبةً من

الأولى ولا تُطابقها. وبعد عشرِ شاشاتٍ تصير عشرَ هويّات.




**العلاج قاعدتان:**




1. **كلُّ الصور في دردشةٍ واحدة.** لا تفتح مشروعاً جديداً لكلّ شاشة.

2. **كلُّ رسالةٍ تبدأ بتذكيرٍ بالنظام.** سطران يكفيان — وهما في النصّ

   المتكرّر أدناه.




---




# ١) الرسالة الأولى — مع أوّل صورة




> اختر لها **صورة «سير المعاملة»** (الشاشة الكاملة بالشريط الجانبيّ) — فيها

> الشريطُ والترويسةُ والبطاقاتُ والخطُّ الزمنيّ معاً، فيلتقط منها النظامَ كلَّه.




```

أنشئ لوحةَ تحكّمٍ لمنصّة SaaS سعوديّة اسمها «تكامل بلس» (Takamol Plus)

لإدارة الموارد البشرية والمالية وخدمة العملاء.




طابِق الصورةَ المرفقة بالضبط: الألوان، المسافات، أنصاف الأقطار، الظلال،

أحجام الخطّ وأوزانه، وتقسيمة الشاشة. الصورةُ هي المرجع لا وصفي.




الأساسيّات:

- عربيّة بالكامل، <html dir="rtl">، خطّ Cairo من Google Fonts.

- React + TypeScript + Tailwind + shadcn/ui.

- الشريط الجانبيّ على **اليمين**، والمحتوى يساره.

- كلُّ الألوان متغيّرات CSS في :root وتُستعمل بأسمائها — لا لونَ مكتوباً

  داخل أيّ مكوّن.




في هذه الرسالة ابنِ ثلاثة أشياء فقط:

1. نظام التصميم: المتغيّرات، الخطّ، سلّم المسافات، أنصاف الأقطار، الظلال.

2. الشلّ: الشريط الجانبيّ (شعار + بنود بأيقونة ونصّ + البند النشط مستطيل

   ممتلئ) والشريط العلويّ (بحث + جرس + ترس + بطاقة المستخدم).

3. الشاشة التي في الصورة.




وابنِ هذه المكوّنات قابلةً لإعادة الاستعمال، فسأطلب بها عشرات الشاشات:

StatCard · DataTable · StatusBadge · Timeline · PageHeader · FilterBar ·

Modal · EmptyState · Skeleton.




لكلّ شاشةٍ فيها بيانات اصنع أربع حالات: تحميل (skeleton لا spinner) ·

فراغ (أيقونة + سطر يشرح + زرّ الفعل) · خطأ · لا صلاحيّة.




استجابة على ١٤٤٠ و١٠٢٤ و٣٩٠ بكسل. على الجوّال الشريطُ الجانبيّ درجٌ

ينفتح بزرّ، والجداول تمرّ أفقيّاً داخل حاوياتها ولا تُفيض الصفحة.




البيانات: لا تبنِ Supabase ولا قاعدة بيانات ولا مصادقة. اجعل كلَّ نداءٍ

يمرّ بدالّةٍ واحدة:

  POST {API_BASE}/rpc/{functionName}

  الترويسة: Authorization: Bearer <token> · Content-Type: application/json

  الجسم: { "data": { ... } }

اقرأ {API_BASE} من متغيّر بيئة، وضع البيانات التجريبيّة في ملفٍّ واحد

mockData.ts.




ممنوع: فواتير مبيعات أو عملاء مبيعات أو مرتجعات بيع (المنصّة مشتريات

فقط) · تغييرُ أسماء الشاشات العربيّة · خطٌّ غير Cairo · شاشاتٌ لم أطلبها.




ولا تبنِ غير الثلاثة حتّى أقول.

```

# ٢) النصُّ المتكرّر — مع كلّ صورةٍ بعدها




> **انسخه كما هو في كلّ مرّة**، وبدّل الاسمَ والمسار. لا تزد عليه.




```

شاشة جديدة — طابِق الصورة المرفقة.




التزم بنظام التصميم والمكوّنات الموجودة في المشروع: نفس متغيّرات :root،

نفس الخطّ والمسافات وأنصاف الأقطار، ونفس StatCard و DataTable و

StatusBadge و PageHeader. لا تُنشئ ألواناً ولا أنماطاً ولا مكوّناتٍ جديدة

إلّا إن كانت في الصورة ولا مقابلَ لها عندك.




الاسم: «__________»

المسار: /__________

أضِفها إلى الشريط الجانبيّ تحت مجموعة: __________




وأربعُ الحالات كالعادة: تحميل · فراغ · خطأ · لا صلاحيّة.

```




**وإن كانت الشاشةُ فيها ألسنة**، أضف سطراً:




```

الشاشة فيها ألسنة: __________ · __________ · __________

اجعلها ألسنةً داخل الشاشة نفسِها بمسار ?tab=، لا شاشاتٍ منفصلة.

```




---




# ٣) نصُّ التصحيح — حين ينحرف




استعمله فورَ أن ترى لوناً أو حافّةً أو حجمَ خطٍّ مختلفاً. لا تؤجّل: كلُّ

شاشةٍ تُبنى على المنحرف تُضاعف العمل.




```

هذه الشاشة خرجت عن نظام التصميم. صحّحها:

- استعمل متغيّرات :root الموجودة فقط — لا ألوانَ مكتوبةً بالـhex.

- نفس نصف القطر والظلّ المستعملين في بقيّة البطاقات.

- نفس أحجام الخطّ وأوزانه.

- نفس المسافة بين البطاقات وبين الأقسام.

قارِنها بشاشة «__________» واجعلهما متطابقتَين في كلّ ما سبق.

```




**وأقوى منه** إن تكرّر الانحراف: خذ محتوى `:root` من `index.css` بعد أوّل

شاشةٍ ناجحة، واحفظه عندك. ثمّ الصقه وقل:




```

هذه هي متغيّرات التصميم المعتمدة. التزم بها حرفيّاً في كلّ شاشةٍ قادمة

ولا تُضف إليها:




<الصق المتغيّرات هنا>

```

## ترتيبُ الإرسال المقترح




ابعث الصورَ بهذا الترتيب لا عشوائيّاً — كلُّ واحدةٍ تُرسّخ ما بعدها:




| # | الصورة | لماذا هذه أوّلاً |

|---|---|---|

| ١ | سير المعاملة (الكاملة) | فيها الشريطُ والترويسةُ والبطاقاتُ والخطُّ الزمنيّ — النظامُ كلُّه |

| ٢ | الميزانيات والأرباح والخسائر | تُرسّخ الرسومَ (خطّيّ · دونات) والجدولَ بأشرطة التقدّم |

| ٣ | لوحة منصّة الأعمال | تُرسّخ لوحةَ المؤشّرات وصندوقَ العمل |

| ٤ | ملفّ الموظّف | تُرسّخ **صفحةَ التفصيل بالألسنة** — وهي قالبٌ يتكرّر كثيراً |

| ٥ | إصدار مكافأة | تُرسّخ **النموذجَ بخطوات** — قالبٌ آخر يتكرّر |

| ٦ | فواتير/جدول أيَّ شاشة قائمة | تُرسّخ **قالبَ القائمة** |

| ٧+ | الباقي | صار عنده القوالبُ الأربعة، فما بعدها يتولّد بسهولة |




**بعد الصور الستّ الأولى** ستكون القوالبُ الأربعةُ عنده (لوحة · تفصيلٌ

بألسنة · نموذجٌ بخطوات · قائمة)، وأكثرُ الشاشات المئة يقع في واحدٍ منها —

فيكفي أن تقول له «نفس قالب شاشة كذا، والأعمدة هي هذه».




والقائمةُ الكاملة للشاشات: **takamul-plus.com/notes/screens/**
